# PICORA-2D

現在の配布版は **1.2.1** です。パーツ名・カラーバーなどの文字が潰れる問題を修正し、背景色の細い縁取りで描画します。起動時はGEC Cellの軸対称 `(r,z)` モデルを開きます。ジオメトリはスケッチによるドメイン作成を既定とし、線分・円弧の輪郭が閉じると自動でパーツへ昇格します。PICORA-1Dと共通のアイコン、パーツ先行の計算領域、名前付き断面積セットに対応しています。ショートカットには専用ICOの参照を設定し、ショートカットからの起動でも共通アイコンを使います。

ES-Simから2D PIC-MCCと2Dプラズマ流体を抽出したWindowsアプリです。NVIDIA GPUを主な計算デバイスとして、直交格子と埋込境界（EB）で導体・誘電体を扱います。平面 `xy` と軸対称 `rz` / `rz_x0`、AMR、RF電極、誘電体の表面電荷、自己バイアス、収束判定、CAD・DXF、2D結果表示を維持しています。

## 起動

ビルド済み版がある場合、ルートの `Start-PICORA.cmd` をダブルクリックするとデスクトップアプリが起動します。インストーラーは `ui/src-tauri/target/release/bundle/nsis/` に生成します。

旧版からの更新は、アプリを閉じて1.2.1のインストーラーを実行してください。インストール時には自アプリのショートカットのアイコン参照を更新し、Windowsへ変更を通知します。通常の完了画面でデスクトップショートカットを新規作成した場合にも参照を設定します。

起動時のGEC Cellは横軸が径方向 `r`、縦軸が軸方向 `z` で、電極・誘電体・シールドの6パーツを含みます。見本の外周寸法と境界条件を保持するため計算領域は手動です。「ファイル → 新規」はパーツのない軸対称 `(r,z)` モデルを作り、計算領域はパーツへの自動追従です。ファイルを開く場合や自動保存から復元する場合は文書の座標系を引き継ぎます。

ソースから準備する場合は、PowerShellで次を実行します。Python依存関係はuv、UIはnpm、デスクトップシェルはTauri 2で管理します。

```powershell
.\scripts\setup.ps1
.\scripts\start.ps1 -Browser
```

ブラウザー版は `http://127.0.0.1:1422`、計算APIは `http://127.0.0.1:8766` です。元のES-Simと設定・ポート・自動保存を分けています。ブラウザー版のサーバーはバックグラウンドで動作し、ログは `.runtime/` に保存します。

ブラウザー版を終了するときは `.\scripts\stop.ps1` を実行してください。デスクトップ版はウィンドウを閉じると計算サーバーも終了します。

開発中にそれぞれ手動起動することもできます。

```powershell
cd backend
uv run --extra gpu --group dist python run_server.py --port 8766
# 別の端末
cd ui
npm run dev
# デスクトップ開発モードは npm run tauri dev
```

## 計算

ツリーの「2D PIC」または「2D流体プラズマ」を選び、設定して実行します。メッシュは直交格子に限定しています。CADの曲線や固体境界は格子に沿って階段状に置き換えず、EBの幾何から処理します。AMRを使う場合も直交格子を局所的に細分化します。

計算領域の外周は軸に平行な矩形です。円や任意の多角形、円弧は内部の導体・誘電体境界として作成します。対応しない外周形状を読み込んだ場合は、画面から外接矩形へ変換できます。

PICはGPU専用です。流体はGPUを既定として、検証やGPUのない環境向けにCPUも選べます。GPUを明示指定した場合、利用できない理由を表示して実行を停止します。CPUへ自動的に切り替えてGPU計算と表示することはありません。CUDA 13対応のNVIDIA GPU・ドライバーを使ってください。配布版にはNVRTCを同梱します。

「CCPデモ」は短い操作確認用の**合成断面積**を含みます。研究用の断面積ではありません。GECセルの例と保存済み結果は元ES-Simのものです。保存済み結果は新たなGPU計算結果と区別して扱ってください。

## パーツ先行のジオメトリ

1. 「パーツ → スケッチからドメイン作成」で輪郭を描きます。線分・円弧・折れ線の端点がつながって閉じると、ドメイン（パーツ）へ自動で昇格します。作成後に導体・誘電体・空間電荷の種類と値を設定し、位置と形を編集します。
2. 「計算領域」の「自動追従」では、全パーツの外接矩形に指定した余白を足して領域を決めます。追加・移動・変形・複製・削除に追従します。余白の既定値は 5 mm です。
3. 領域を固定したい場合は「手動」へ切り替えます。既存ファイルは手動として開くため、以前の計算条件をそのまま維持します。
4. パーツと領域の変更は同じ操作履歴で元に戻せます。外周の境界条件も対応する辺に引き継ぎます。

作成モードの既定は「スケッチ → ドメイン」です。同じレイヤのドメイン用スケッチを接続し、閉じた面に使った輪郭だけをパーツへ置き換えます。開いた線やはみ出した部分はスケッチに残ります。折れ線は始点をクリックして閉じ、Enterで開いたまま確定できます。線分は続けて描くか、Enterで区切って別々に描いても閉鎖を認識します。接点は端点・交点スナップを使って合わせられます。

矩形・円も使用でき、「直接パーツ」では従来どおり作成します。閉じた輪郭を線のまま残す場合は「補助スケッチ」に切り替えます。旧文書とDXFのスケッチは補助線として維持し、スケッチページの「補助スケッチとして残す」を外すか、複数選択して「ドメイン用にする」で昇格できます。ロックしたレイヤは自動昇格の対象にしません。

昇格と計算領域の追従は同じUndo/Redo操作に含まれます。未閉鎖のスケッチ・用途と昇格済みのパーツを保存して再編集できます。軸対称では径方向の領域下限を0以上に保ち、軸をまたぐパーツの負径側は計算領域の外になります。

旧外周の分割辺を矩形の一辺へまとめる場合は、同じ境界条件と式の参照を統合して引き継ぎます。異なる電位・境界種類・式・粒子反射が同じ一辺へ重なる場合は、説明を表示して変換を止め、元の手動設定を保ちます。

## 衝突断面積セットの登録

1. ツリーの「衝突断面積」を開きます。
2. セット名を付け、LXCatファイルを読み込むか、CSVを選択・貼り付けます。LXCatはファイル内の複数過程をまとめて1セットに登録します。CSVのヘッダーは `energy[eV],sigma[m2]`、データはエネルギーの昇順です。
3. CSVではガス、入射粒子、衝突種別、閾値を指定します。複数ファイルを同じセットへ登録でき、登録済みセットへの追加もできます。出典は必須です。未知のガスには質量 `[amu]` も指定してください。
4. 登録後はセットを選び、PICの電子／イオン衝突または流体の電子係数へ適用します。セット内の対象粒子に対応する過程とガス圧・温度を置き換えます。変更は元に戻せます。セットの名前変更、複製、過程の追加・削除、セット単位の削除ができます。
5. 流体でBoltzmann係数を使う場合は、適用後に係数表を再生成します。イオンの輸送係数も使用ガスに合わせて設定してください。

負値、NaN/Infinity、重複・逆順エネルギー、不明なCSV単位、非弾性衝突の閾値未満の非零断面積を拒否します。現在のソルバーに変換できない種類は警告します。混合ガスとして一律に合算しないよう、計算への適用は単一ガスに限定しています。

登録ライブラリーはデスクトップ版ではアプリ設定ディレクトリーの `cross_sections.json`、起動スクリプトでは `data/cross_sections.json` に保存します。`PICORA_XS_REGISTRY` 環境変数で保存先を指定できます。適用済みの断面積と出典はプロジェクトにも埋め込み、登録を削除しても保存した計算条件を保ちます。

旧形式の個別登録は、内容を維持したセットへ自動移行します。移行前のJSONは `.v1.bak` に保存します。

## テーマ

「表示 → テーマ」で「システム設定」（既定）、「ライト」、「ダーク」を選べます。設定を保存し、システム設定ではOSのテーマ変更に追従します。色のトークンは `ui/src/styles/theme.css` に集約しています。

## 検証とビルド

```powershell
cd backend
uv run --extra gpu --group dist pytest
uv run --extra gpu --group dist python run_server.py selftest --require-gpu
cd ..\ui
npm run typecheck
npm test
npm run build
cd ..
.\scripts\build_app.ps1 -RequireGpu
```

元アプリの共通数値処理が必要なため、内部Pythonパッケージ名と一部の共通モジュールは `es_sim` のまま保持しています。公開する計算ジョブは `pic` / `fluid2d` と流体系数生成用の `boltz` です。1D、DSMC、粒子軌道追跡、定在波の画面・実行経路は含みません。GPU PICの未対応機能（粒子注入・FN放出など）は引き継いでいません。

Windowsの実行時アイコンは、バックエンドの環境から `uv run --no-sync python ../scripts/check_window_icon.py --launch --force-close` で検証できます。`WM_GETICON`でタスクバー用・タイトルバー用の画像を取得し、共通ICOと描画結果を比較します。`--force-close`は検証で起動したアプリだけを、通常の終了が10秒以内に完了しない場合に強制終了します。既存PIDの読み取り検証には `--pid <PID>` を使います。

ショートカットの実画像は `--shortcut <ショートカット.lnk>` で検証できます。Windows Shellが返す画像を、共通ICOに標準のリンク矢印を付けた画像と比較します。既存のインストールだけを修復する場合は `scripts/repair_shortcuts.ps1` を実行します。対象はそのインストール先の `picora-2d.exe` を指すリンクに限定し、変更前のリンクを `.runtime/shortcut-backups/` へ保管します。`-CheckOnly` で参照を読み取り確認できます。
